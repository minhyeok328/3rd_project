## 처리 단계

| 단계 | 구현과 정책 |
| --- | --- |
| 라우팅 | ChatOpenAI 응답에 fixed가 있으면 이름 검색, 없으면 임베딩 검색 |
| 슬롯 | JSON Schema strict로 필요한 문자열 키 강제, 누락·타입 검사 |
| 고정 검색 | restaurant/menu/user 이름 LIKE 조회 → 관계 이동 → 중복 코드 제거 |
| 임베딩 검색 | 슬롯별 상위 8개 엔티티 → 식당 코드 이동 → 검색 결과가 있는 슬롯 수별 후보 수 제한 |
| 재정렬 | 질문 토큰 일치 +2, 후보 키워드가 질문에 포함되면 +3 |
| 생성 | 프롬프트·경로·슬롯·후보·이전 대화를 전달하고 한국어 답변 생성 |

소스: [pipeline.py](../../src/pipeline.py), [slot_extractor.py](../../src/slot_extractor.py), [utils.py](../../database/sql/utils.py), [retriever.py](../../src/retriever.py), [generator.py](../../src/generator.py).

## 슬롯 스키마

- embedding: `category`, `tag`, `menu`, `food`, `review`
- fixed: `restaurant`, `menu`, `user`

빈 조건은 빈 문자열입니다. 입력이 비어 있으면 슬롯 도구는 빈 사전을 구성하지만, `run_qa` 전체가 빈 질문을 사전에 거부하도록 구현된 것은 아닙니다.

## 후보 선택의 실제 동작

임베딩 검색은 식당 코드가 한 건 이상 나온 슬롯 목록을 모은 후 `cnt_space = [5, 3, 2, 1, 1]`에서 해당 목록 수에 대응하는 수만큼 각 목록에서 식당을 가져옵니다. 검색 결과가 없는 슬롯은 제외하므로 다른 슬롯의 후보 할당량이 늘어날 수 있습니다. 모든 조건의 교집합을 요구하지 않습니다. 상세 조회 SQL도 이 단계의 유사도 순서를 명시적으로 보존하지 않습니다.

재정렬은 학습된 랭커나 BM25가 아니라 부분 문자열 점수입니다. 상위 K 안의 양수 점수 후보를 사용하며, 모두 0점이면 원래 후보의 앞 K개로 폴백합니다. 이 순서와 후보 누락이 최종 답변에 영향을 줍니다.

## 모델 설정

기본 라우터·생성 모델은 `gpt-4.1-mini`, 슬롯 추출 모델은 `gpt-4o-mini`입니다. 이는 저장소 설정값이며 현재 외부 서비스 가용성 검증을 뜻하지 않습니다. 런타임 DB 임베딩은 `text-embedding-3-small`로 고정되어 있습니다. 학습·파인튜닝 코드는 없습니다.

## 생성 규칙과 한계

[system_prompt.txt](../../prompts/system_prompt.txt)는 후보 안에서 한 식당을 선택하고 메뉴·리뷰·주소를 해당 데이터에서 가져오도록 지시합니다. 후보가 없으면 찾을 수 없다고 답하게 합니다. 이러한 규칙은 모델 지시이며 출력 사실성을 보장하는 결정적 검증은 아닙니다.

대화 문맥은 생성기에만 전달됩니다. 라우터와 슬롯 추출기는 현재 질문만 받으므로 이전 대화를 참조하는 후속 질문에서 검색 조건을 충분히 복원하지 못할 수 있습니다.

평가는 [검증과 한계](../10-quality/verification-and-limitations.md)에서 확인합니다.
