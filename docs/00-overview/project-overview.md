# 프로젝트 개요

[문서 목록](../README.md)

## 목적

사용자가 식당 이름을 모르더라도 음식 종류·분위기·리뷰 조건으로 후보를 탐색하고, 추천 이유를 원천 데이터와 함께 확인하도록 돕습니다. 대상은 수집된 신대방삼거리 식당 데이터입니다.

## 구현 범위

| 영역 | 구현 |
| --- | --- |
| 검색 | 이름 기반 SQL 검색과 슬롯별 임베딩 검색 |
| 추천 | 라우팅 → 구조화된 슬롯 → 관계 데이터 조회 → 키워드 재정렬 → LLM 답변 |
| 화면 | 검색/채팅 전환, 식당 카드·상세, 지도 |
| 데이터 | HTML 수집·CSV 정제·SQLite 적재용 노트북과 검색 함수 |
| 평가 | 동일한 50문항 골드셋과 3개 저장 리포트 |

## 구현 경계

- 기본 실행 파일은 [main.py](../../main.py)입니다. [experiments/frontend/app.py](../../experiments/frontend/app.py)는 별도 초기 실험이며 동일한 진입점이 아닙니다.
- [api/server.py](../../api/server.py)와 [scripts/build_index.py](../../scripts/build_index.py)는 설명 주석만 있습니다. HTTP API나 일괄 인덱스 구축 기능을 제공하지 않습니다.
- 최종 DB는 이 체크아웃에 없습니다. 소스 CSV를 최종 DB와 동일한 완성 데이터로 취급하지 않습니다.
- 계정·인증·영속 대화 저장·자동 데이터 갱신·운영 배포 설정은 구현되어 있지 않습니다.
- 추천 한 곳은 프롬프트의 출력 규칙입니다. 반환값을 검증해 식당 한 곳으로 강제하는 후처리는 없습니다.

## 데이터와 외부 연동

[테이블별 CSV](../../database/processed/db_csv_tablewise)에는 식당 100행, 메뉴 2,008행, 리뷰 422행이 있습니다. 이는 현재 파일의 행 수이며 실행 DB의 상태나 최신 영업 정보를 의미하지 않습니다. 대화 질문·후보 문맥은 OpenAI 호출에 사용되고, 지도는 Kakao SDK를 불러옵니다.

[개발 환경](../01-getting-started/development-environment.md)에서 실행 전 필요한 파일을 확인하고, [검증과 한계](../10-quality/verification-and-limitations.md)에서 평가 해석과 운영 제약을 확인합니다.
